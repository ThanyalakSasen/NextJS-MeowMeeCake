# คูปอง / โค้ดส่วนลด / หน้าร้านหลัก — แก้รอบ 2026-10-26

## แจ้งเตือนคูปองในเว็บ (`src/services/couponNoticeService.ts`)
- แลกแต้มเป็นคูปอง → กระดิ่งในเว็บของลูกค้าคนนั้น พร้อมรหัส (`coupon_code`) · ไม่ส่ง LINE (ไม่กินโควตา)
- ร้านสร้างโค้ดใหม่ที่ใช้ในเว็บได้ (ไม่ใช่โค้ดแลกแต้ม · มีช่องทาง online · เปิดอยู่ · ยังไม่หมดอายุ) → แจ้งลูกค้าทุกคน (role `customer`)
  แสดงตั้งแต่วันเริ่มโปร (`visible_at`) · `ref_type: "promotion"`
- ลบโค้ด → ซ่อนแจ้งเตือนของโค้ดนั้น · กู้คืนโค้ด → แสดงอีกครั้ง

## กันใช้โปรเกินโควตา
- `orderService` / `preorderService`: บันทึก `PromotionUsages` ไม่สำเร็จ **ทุกสาเหตุ** = ออเดอร์/พรีออเดอร์ไม่สำเร็จ (saga คืนสต็อก/โควตา/คูปอง/แต้ม)
  (เดิม error ที่ไม่ใช่ 422 ถูกปล่อยผ่าน — ได้ส่วนลดโดยไม่มีบันทึกการใช้)
- `couponService.applyUserCoupon`: บันทึกการใช้ไม่สำเร็จ → คืนคูปองเป็น available + คืน `used_count` ก่อนโยนต่อ

## โค้ดเฉพาะหน้าร้าน
ตรวจช่องทางก่อนเงื่อนไขอื่น → กรอกในเว็บได้ข้อความ "โค้ดนี้ใช้ได้เฉพาะที่หน้าร้านเท่านั้น" เสมอ (แม้โค้ดหมดอายุ/ปิด/เต็ม)

## บั๊กส่วนลด (`lib/discountEngine.ts` · `couponService.ts` · `promotionService.ts` · `promotionUsageService.ts`)
| บั๊ก | แก้ |
|---|---|
| `usage_limit` / `max_user_per_user` = 0: คูปองถือว่าไม่จำกัด แต่กรอกโค้ดถือว่าเต็มแล้ว | ทุกที่ใช้ `lib/promoCode.positiveLimit` — ค่า > 0 เท่านั้นที่เป็นเพดาน |
| `max_discount_amount` = 0 ตัดส่วนลด % เหลือ 0 → "ส่วนลดเป็น 0" | เพดานมีผลเฉพาะ > 0 |
| `applicable_channels: []` = ใช้ไม่ได้ทุกช่องทาง | [] = ทุกช่องทาง |
| คูปองของโปรที่จำกัดสินค้า/หมวด ลดได้ทั้งตะกร้า (ไม่เก็บขอบเขต) | เก็บ `applicable_products/categories/min_quantity` ตอนแลก · คูปองเก่าอ่านจากโปรต้นทาง |
| "SAVE 10" ≠ "SAVE10" (trim แค่หัวท้าย) | `normalizePromoCode` ตัดช่องว่างทุกตำแหน่ง ทั้งตอนตั้งและตอนกรอก |

## โค้ดส่วนลดในพรีออเดอร์
`POST /api/shop/preorders` รับ `promotion_code` (ใช้แทนคูปองของฉัน) · พรีวิว `POST /api/shop/promotions/validate` + `lines`
(หน้าเว็บบังคับกดใช้โค้ดใหม่เมื่อรายการ/จำนวน/ที่อยู่/วิธีรับเปลี่ยน)

## รีวิว
ข้อความเมื่อรีวิวไม่ได้ (`reviewService.REVIEW_BLOCK_MESSAGE`) ตรงกับที่หน้าเว็บแสดง — ยกเลิก → ยังไม่ชำระ → ยังไม่สำเร็จ

## หน้าร้านหลัก (`weekly_markets[].is_main`)
schema เดิมไม่มี field นี้ บันทึกทีไรธงที่ระบบเดิมเขียนไว้หาย → หน้าร้านหลักตกไปลำดับ 2 และระบบที่อ่านเวลาเปิดจากหน้าร้านหลักใช้เวลาเก่า
- เพิ่ม `is_main` · มีได้ 1 แห่ง · อยู่ลำดับแรกเสมอ (`storeService.withMainFirst`)
- client ไม่ส่ง `is_main` = ใช้ค่าเดิมของรายการนั้น
- ข้อมูลเก่าไม่มีธง: `ensureWeeklyMarketsReady` ตั้งรายการชื่อ "หน้าร้าน…" (ไม่งั้นรายการแรกที่เปิด) เป็นหลักให้ครั้งเดียว
